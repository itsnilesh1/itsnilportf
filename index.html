Security tool

Laptop Intruder Detection System

Intelligent surveillance that triggers on failed logins — captures the intruder silently and fires alerts with location in real time.

  • Detects failed login attempts autonomously
  • Silent photo/video capture via OpenCV
  • Telegram & email alerts with evidence
  • Location tracking included
PythonOpenCVSMTPTelegram APIGPS
How it works
  1. Login attempt monitor. Hooks into the OS authentication layer using system logs and PAM. Any failed login triggers the detection pipeline immediately.
  2. Webcam capture. OpenCV captures a burst of photos and 10 seconds of video of whoever is in front of the laptop.
  3. Location lookup. Public IP geolocation APIs return the approximate location of the laptop.
  4. Telegram and email alert. Within about 3 seconds, the photo, video clip, timestamp and location are sent through the Telegram Bot API and SMTP email.
  5. Evidence logging. Captures are timestamped and stored locally in an encrypted folder. Each incident gets a unique ID so repeated attempts can be tracked.

Login event monitoring and triggers
Security perspective. Insider attacks, shoulder surfing and physical device theft are among the most overlooked attack vectors. Automating evidence capture on the device goes beyond typical software-only security tools.

Challenges and how I solved them

  • Speed: a 3-second alert window. The first version took 8–10 seconds from trigger to alert. Async Python (asyncio) runs capture and upload in parallel and brings it under 3 seconds.
  • Reliability without internet. If Wi-Fi is down, alerts queue locally and send as soon as connectivity returns, so no evidence is lost.
ML + fintech

FacePay — Face Recognition Payment

Biometric Android payment concept using face recognition as an alternative to PIN-based authentication, redirecting to UPI apps after identity verification.

  • Face recognition as an authentication factor
  • Seamless UPI app redirection
  • ML-powered identity verification
  • Explores biometric authentication as an alternative mechanism
JavaAndroid StudioML KitUPI API
How it works
  1. Face enrollment. On first launch, the user's face is captured from several angles with the front camera. ML Kit face detection processes the images and the face template is stored on the device.
  2. Liveness detection. To resist photo and video spoofing, the app asks the user to blink, smile or turn their head.
  3. Face matching. At payment time the live camera feed is compared against the stored template, with a high match threshold balancing security and usability.
  4. UPI deep link redirect. After a successful match, the app builds a UPI deep link with the merchant details and opens the user's UPI app (GPay, PhonePe, BHIM) for final confirmation.
  5. Transaction logging. Every attempt, successful or not, is logged with timestamp, match score and device ID. Three failed attempts trigger a lockout to block brute force.

Security perspective. PINs and passwords can be stolen, guessed or shoulder-surfed. FacePay explores biometric authentication as an alternative, with on-device processing so biometric data never leaves the phone. It is a student exploration of privacy-conscious security design, not a claim of complete or unbreakable security.

Challenges and how I solved them

  • Anti-spoofing. Photo attacks are the main weakness of face authentication. Multi-frame liveness checks that need real facial movement block printed photos and screen videos.
  • Lighting variation. Tuned ML Kit parameters and added image preprocessing (histogram equalization) to keep recognition steady across lighting conditions.
  • UPI app compatibility. UPI apps handle deep links differently. Tested with GPay, PhonePe, Paytm and BHIM, and built a layer that detects installed apps and builds the right link format.
Hardware

RFID Attendance System

Built and demoed at TechFusion Fest — a hardware-software attendance system with real-time RFID tracking and automated reporting.

  • Contactless RFID attendance tracking
  • Real-time hardware and software sync
  • Automated reporting pipeline
  • Showcased at TechFusion Fest, ADYPSOE
RFID ModuleArduinoPythonDatabase
How it works
  1. Card tap detection. Each student has a unique 13.56 MHz MIFARE card. Tapping the RC522 reader sends the card's UID to the Arduino Uno over SPI.
  2. Arduino serial processing. The Arduino debounces repeated reads (1-second lockout per card) and sends the UID to the computer over USB serial at 9600 baud.
  3. Python backend. A pyserial script receives the UID, looks up the student's name and roll number in SQLite and records the timestamp within 200 ms of the tap.
  4. Database and records. SQLite holds student profiles and attendance records. Duplicate entries within a 10-minute window are rejected.
  5. Real-time dashboard. A Tkinter dashboard shows each tap live with name, photo and time. Teachers can export CSV reports for any date range.

Stack in depth

Student ID cards with unique hardware UIDs
Security perspective. RFID cards can be cloned with tools like Proxmark3. This design treats UIDs as identifiers, not secrets. A production version would add encrypted card data and server-side validation to prevent cloning.

Challenges and how I solved them

  • Preventing double registration. Readers can fire several reads per second. A 1-second lockout in the firmware and a 10-minute duplicate window in the database stop accidental double marking.
  • Serial reliability. USB serial links can drop on Windows. Auto-reconnect logic in Python re-establishes the port without restarting the app.
  • Demo reliability. For the TechFusion Fest demo I ran 48-hour stress tests with 500+ card taps, fixed UID parsing edge cases and prepared a backup SD card with the software pre-configured.
